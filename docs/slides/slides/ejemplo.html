La consulta es corta porque la complejidad está en la capa, escrita una vez. El SQL lo genera Ontop: nadie lo escribe ni lo mantiene.

Cruza tres fuentes: el ensayo, el target del fármaco y la jerarquía de enfermedades. El LLM escribió 1.543 caracteres de SQL, adivinando qué fármaco nombra cada ensayo. Con Rastro escribió 435 de SPARQL, solo conceptos. Ontop generó 742 de SQL: joins simples sobre enlaces revisados. En las 20 preguntas, el SPARQL promedia la mitad que el SQL (368 contra 726). En preguntas muy simples el SQL puede ser más corto: la ventaja aparece al cruzar fuentes.
